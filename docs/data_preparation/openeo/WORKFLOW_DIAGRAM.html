openEO parcel statistics workflow

How OpenEOZonalStats turns parcel polygons into one ML-ready row per parcel: what is requested from openEO, how the downloaded pixels are cleaned and filled, and how the parcel statistics are calculated. Read from the code in src/data_preparation/. Defaults are the constructor defaults.

runs on your machine runs on the openEO backend (Copernicus Data Space) flag = default input that controls the step only if … step is conditional

1 · Prepare

your machine · once per run
1

Validate the configuration

Dates are parsed and ordered, the EPSG must be a projected CRS, band and index names are checked, and at least one Sentinel-1 or Sentinel-2 output must be selected. Bands needed by an index are added to the download list automatically, without becoming outputs themselves.

start_dateend_dateworking_epsgoutput_dirsentinel2_bands = B02,B03,B04,B05,B08sentinel2_indices = Nonesentinel1_bands = Nonesentinel1_indices = None
2

Prepare the parcels

Geometries are repaired with make_valid, only polygon parts are kept, empty parcels are dropped, the ID column is cast to string and must be unique (it is created from the index when missing), and the parcels are reprojected to EPSG:4326 for openEO. All other attribute columns are kept and reach the final file.

parcelsparcel_id_field = "parcel_id"
3

Check for reusable results and build the cache key

If the three final files exist and the completion manifest matches the current settings and parcel IDs, the run returns them immediately. Otherwise a 16-character signature of the processing options, parcel IDs and geometries names the raw-cube cache folder monthly_cubes/<signature>/.

resume_completed_partitions = False
4a

Split into jobs: OpenEOZonalStats

Parcels are grouped by the 50 km grid cell of their centroid (in working_epsg), sorted by position, and cut into jobs of at most 5,000 parcels. Each job sends the parcel polygons themselves.

Constants: GRID_SIZE_METRES 50,000 · MAX_FEATURES_PER_JOB 5,000

4b

Split into jobs: OpenEOJobManagerZonalStats

One job per square tile. Each parcel belongs to the tile holding its representative point; the tile is requested as a buffered bounding box, so a parcel on an edge is still fully covered.

tile_size_metres = 50000tile_buffer_metres = 500fit_tiles_to_parcels = False
↓one process graph per batch

2 · Acquire from openEO

openEO backend · once per batch
5

Sentinel-2 branch

only if any S2 band or index is selected
  1. Load SENTINEL2_L2A for the date range: requested bands, index source bands and the SCL band. Scenes above the cloud-cover limit are dropped.
  2. Filter spatially to the batch parcels.
  3. Resample reflectance to 10 m (bilinear) and scale by 0.0001.
  4. Mask invalid pixels using SCL (resampled nearest): classes 0 no data, 1 defective, 3 cloud shadow, 8 and 9 cloud, 10 cirrus, 11 snow.
  5. Buffer clouds: classes 3, 8, 9, 10, 11 are grown by one pixel with a 3×3 kernel and masked too.
sentinel2_max_scene_cloud_cover = 70
6

Sentinel-1 branch

only if any S1 band or index is selected
  1. Load SENTINEL1_GRD for the date range: VV and/or VH, optionally one orbit direction only.
  2. Filter spatially to the batch parcels.
  3. Backscatter: sigma0 over the ellipsoid, Copernicus 30 m DEM, kept in linear power (no dB conversion).
sentinel1_orbit_direction = "BOTH"
7

Aggregate over time

Each sensor cube is reduced into bins of temporal_period, labelled by the bin start date. Bins are half-open and the last calendar day is included.

  • mean, median, min, max, sum: one composite image per bin, per pixel.
  • none: no remote aggregation. Every acquisition is downloaded and the pooling happens later, at step 18.
temporal_period = "1M"temporal_reducer = "median"
8

Put both sensors on one grid

Sentinel-1 is resampled (bilinear) onto the Sentinel-2 grid and the cubes are merged. With Sentinel-1 only, it is resampled to 10 m. The cube keeps the source projection; nothing is reprojected to working_epsg.

9

Run the batch job and download NetCDF

Jobs run in waves. Each result is written to a .partial.nc file and renamed to batch_00001_monthly.nc only when complete, so an existing file is always a finished download and is reused on the next run. Login uses the username and password when given, otherwise the interactive OIDC flow.

batch_workers = 1openeo_username = Noneopeneo_password = None

Tile variant instead uses: openeo_parallel_jobs 2 · job_poll_seconds 30 · max_job_retries 3 · job_retry_delay_seconds 60 · openeo_job_options · openeo_auto_memory_retry True · openeo_max_executor_memory "8G"

↓raw cube: time × band × y × x

3 · Clean and fill the pixels

your machine · per batch, one band × time-step layer at a time
10

Open the cube and align the parcels

The cube's own CRS and transform are read, and the batch parcels are projected into it. Batches run in parallel processes; a batch with saved statistics is skipped.

batch_workers = 1
11

Remove outliers (IQR)

only if remove_outliers = True

For each layer, Q1 and Q3 are taken over all valid pixels of the batch raster. Pixels below Q1 − k·IQR or above Q3 + k·IQR become null. Layers with too few valid pixels are left untouched. Bounds are never shared between dates or bands.

remove_outliers = Falseiqr_quantiles = (0.25, 0.75)iqr_multiplier = 1.5iqr_min_valid_pixels = 20

The values that survive this step are the "observed" pixels. Their mask is stored so every later fill can be traced.

12

Coverage guard

only if fill_nulls = True

A layer is filled only when its observed share of pixels reaches the minimum. A layer below it stays as it is and is also hidden as a donor, so a mostly cloudy date cannot spread into good dates.

fill_nulls = Falseminimum_observed_fraction_for_fill = 0.20
13

Fill cascade: each stage only touches pixels that are still null

only if fill_nulls = True

13a · Temporal fill (same pixel, other dates)

For each null pixel, look at the same pixel on neighbouring time steps. past_only copies the closest earlier value. bidirectional averages the closest earlier and later values, or uses whichever one exists. A window of 3 reaches one step each way; wider windows retry the gaps that remain, nearest step first, and always read original observations, never values filled a moment ago. None searches without limit. Steps where the band has no observation anywhere (Sentinel-1 dates for a Sentinel-2 band) are not counted as steps.

temporal_fill_mode = "past_only"temporal_fill_window_sizes = (3,)temporal_fill_block_rows = 2048

13b · Spatial mean fill (same date, neighbouring pixels)

Each remaining null takes the mean of the valid pixels in a square window around it, when there is at least one. Windows run in order and only while nulls remain, and a larger window can use values written by a smaller one. Allowed settings: (3,), (3, 5), (3, 5, 7) or (3, 5, 7, 9).

spatial_fill_window_sizes = (3, 5, 7)

13c · Interpolation (last resort)

Whatever is still null is interpolated per layer. nearest copies the nearest valid pixel, optionally only within a maximum distance. idw needs the maximum distance. kriging needs the variogram maximum distance.

interpolation_method = "nearest"interpolation_max_distance_in_meters = Noneinterpolation_variogram_lags = 15interpolation_variogram_max_distance_in_meters = None
14

Calculate indices from the cleaned bands

Indices are computed locally, per pixel and per time step, from the cleaned and filled bands, so an index never has its own separate cleaning. Sentinel-2: NDVI, NDWI, MNDWI, NDMI, NBR, GNDVI, EVI, SAVI, MSAVI, NDRE, PSRI, CI. Sentinel-1: R = VV / VH and RVI = 4·VH / (VV + VH). A zero denominator gives null. Each index is also computed from observed-only and observed-plus-temporal bands to record whether its value was observed, temporally filled or spatially filled.

sentinel2_indicessentinel1_indiceskeep_cleaned_checkpoint = False

Checkpoints on disk: …_cleaned.nc (bands, removed afterwards unless kept), …_final.nc (bands and indices with the two provenance masks), …_cleaning_report.parquet.

↓final cube: period × output variable × y × x

4 · Parcel statistics

your machine · per parcel
15

Select the parcel's pixels

The parcel is rasterised once on its own bounding window with all_touched=True: every pixel the polygon touches belongs to the parcel. The same mask is reused for all variables and dates.

16

Require a real observation

only if require_parcel_observation = True

A date on which none of the parcel's pixels was observed for that variable is set to null, so a statistic is never built from filled values alone.

require_parcel_observation = False
17

Pool acquisitions into the period

only if temporal_reducer = "none"

All valid parcel pixels of every acquisition inside the bin are pooled into one sample. With any other reducer each bin already holds one composite image.

18

Reduce to statistics

For every period and output variable the valid pixels are reduced to the requested statistics. mean is always included. Options: median, sd (sample, n − 1), min, max, range, p10, p25, p75, p90. Nulls are ignored; a parcel with no valid pixel gets null.

spatial_statistics = ["mean"]
19

Attach quality metrics

Per parcel: intersected_pixel_count, pixel_area, meets_minimum_pixel_count (a flag only, small parcels are kept), counts and ratios of temporally and spatially filled values, and data_reliability_score = observed values ÷ expected values over all periods and variables.

minimum_parcel_pixels = 3
20

Save the batch

Batch statistics and the cleaning report are saved to Parquet so a restart skips the batch. Only after that are the batch's NetCDF files deleted, if requested.

remove_nc_after_completion = False
↓long table: one row per parcel × period

5 · Assemble the outputs

your machine · once per run
21

Combine batches and add derived features

Batches are concatenated and sorted by parcel and period. Geometry features are computed in working_epsg: area, compactness, perimeter to area ratio, shape index, elongation, interior area ratio, shape complexity score. Where the source statistics exist, each variable also gets variance, coefficient of variation, range, IQR, Bowley skewness and the p90 − p10 spread.

working_epsg
22

Pivot to one row per parcel

Period rows become dated columns named VARIABLE_statistic__YYYYMMDD, for example NDVI_median__20240701. Missing periods are added as null columns so every partition has the same schema. The original parcel attributes and geometry are attached.

23

Write the files to output_dir

  • satellite_parcel_time_stats.geoparquet: the wide, dated table for ML.
  • satellite_parcel_annual_stats.geoparquet: dated columns replaced by the mean, min, max and standard deviation over the periods of each variable's _median columns.
  • satellite_pixel_cleaning_report.csv: per batch, period and variable, the IQR bounds, outlier count and nulls left after each fill stage.
  • satellite_partition_completion.json and four log files (orchestration, source, raster filling, parcel statistics).

Things to know before choosing values

  • Cleaning is off by default. With remove_outliers=False and fill_nulls=False, steps 11 to 13 are skipped and statistics use only the cloud-masked pixels openEO returned.
  • IQR bounds and the coverage guard are measured over the whole batch raster for that band and date, not per parcel. Changing how parcels are batched or tiled can therefore change which pixels count as outliers.
  • In ParcelStatsBase: the spatial_fill_window_sizes defaults to (3, 5, 7), and temporal_fill_block_rows defaults to 2048.
  • Raw downloads are keyed by acquisition settings and parcels; cleaned checkpoints are keyed by the cleaning settings. Changing only a fill option reuses the downloaded cubes and redoes the local work.
