EDA workflow

How EDAPipeline profiles a table, usually the parcel statistics output, and produces the report, the diagnostic tables, the row-level outlier flag and a first feature proposal. Read from the code in src/eda/. Defaults are those of EDAConfig.

flag = default input that controls the step only if … step is conditional

1 · Set up

once per run
1

Validate the settings and prepare the output folder

The input must be a pandas DataFrame or GeoDataFrame with at least one row. Numeric settings are range-checked. With the default reset, everything already in output_dir is removed so the run leaves one consistent set of files.

output_dirreset_output_dir = Truereport_titlerandom_state = 42
2

Sort the columns into roles

  • Numeric: numeric dtype. Categorical: everything that is neither numeric nor datetime. Datetime: datetime dtype. Geometry is handled separately.
  • Numeric features are the numeric columns without the target, the ID and earlier EDA diagnostics (is_outlier, mahalanobis_*, any eda_* column), so a rerun never analyses its own output.
  • Target task: auto treats a numeric target as regression and anything else as classification. Set classification when crop classes are stored as numbers.
target_column = Nonetarget_task = "auto"id_column = None
↓typed column lists

2 · Profile the data

every column, no target needed
3

Column profile and data-quality flags

Each column gets its type, missing share and unique share. A column can collect several flags:

  • constant (high): one or no distinct value.
  • high_missing (medium): missing share at or above the threshold.
  • id_like_or_nearly_unique (medium): almost every value is different.
  • quasi_constant (medium): one value covers nearly all non-missing rows.
  • rare_category_heavy (low): for categorical columns with at least 5 levels, half or more of the levels occur in at most 1% of rows.
high_missing_percent_threshold = 40.0quasi_constant_threshold = 0.98categorical_association_max_unique_ratio = 0.95
4

Descriptive summaries

Numeric and robust numeric statistics, categorical top values, datetime ranges, missingness (including columns that are missing together) and the target distribution. With a geometry column: CRS, missing, empty and invalid geometries, geometry types and bounds. Area and length are summarised only for a projected CRS.

max_categories = 20include_geospatial = True
5

Normality tests

Each numeric feature is tested with Shapiro-Wilk, D'Agostino, Jarque-Bera and Anderson-Darling. Columns longer than the sample size are sampled reproducibly. The hint is likely_normal only when both D'Agostino and Jarque-Bera give p ≥ 0.05.

normality_sample_size = 5000
6

Univariate outliers

Per numeric feature: how many values fall outside the IQR fences (Q1 − k·IQR, Q3 + k·IQR) and how many have an absolute z-score above the threshold. Counts only; no value is changed.

iqr_multiplier = 1.5outlier_zscore_threshold = 3.0
7

Correlation, multicollinearity and categorical association

  • Pearson and Spearman matrices over the numeric columns. Pairs with absolute Pearson at or above the threshold are listed as strong.
  • Variance inflation factors for the first max_features_per_plot numeric features in plot-priority order, after median imputation and standardisation. VIF ≥ 5 and ≥ 10 are labelled.
  • Chi-square and Cramér's V for every pair of categorical columns, skipping constant and nearly unique ones.
correlation_threshold = 0.75max_features_per_plot = 30categorical_association_max_unique_ratio = 0.95
↓profile tables

3 · Target evidence and feature proposal

only with a target column
8

Test every feature against the target

only if target_column is set
Target taskNumeric featureCategorical feature
ClassificationKruskal-Wallis across classes, effect size epsilon² (ANOVA eta² also reported)Chi-square, bias-corrected Cramér's V
RegressionSpearman correlation (Pearson and Kendall also reported)Kruskal-Wallis of the target across levels, epsilon²

p-values are corrected within each test family with Benjamini-Hochberg, giving a q-value. Effect sizes are labelled: epsilon² ≥ 0.14 large, ≥ 0.06 moderate, ≥ 0.01 small; Cramér's V or |Spearman| ≥ 0.5 strong, ≥ 0.3 moderate, ≥ 0.1 weak. For a classification target, each column's missingness is also tested against the target.

feature_selection_alpha = 0.05
9

Build the feature proposal: six criteria, in order

only if target_column is set
  1. Hard exclusions: target, ID, geometry, EDA diagnostics and the configured exclusions are set to exclude.
  2. Data quality: constant, quasi-constant and high-missing columns are set to exclude.
  3. Target evidence: a moderate, large or strong effect with q ≤ alpha is set to use. A meaningful effect without significance, or a significant but weak one, goes to review. Limited evidence is exclude.
  4. Redundancy: going down the ranking, a use feature whose |Spearman| (numeric) or Cramér's V (categorical) with an already kept feature reaches the threshold moves to review.
  5. Shortlist cap: use features beyond the maximum move to review.
  6. Train-only validation: not done here. The ML pipeline does it.

Result: feature_selection_proposal.csv with one action per feature and the five pass/fail columns, plus a text summary.

feature_selection_alpha = 0.05feature_selection_redundancy_threshold = 0.90feature_selection_max_features = 50feature_selection_exclude_columns = ()print_feature_selection_summary = True
↓ranked features

4 · Multivariate diagnostics

numeric features, row by row
10

PCA summary

Explained variance per component from the first max_multivariate_features numeric columns, after median imputation, removal of constant columns and standardisation.

max_multivariate_features = 15
11

Outlier vote: five methods, one vote each

Run on the best-ranked max_multivariate_features numeric feature columns, in the shared feature priority used by the charts: proposal rank first (when a target is set), then data quality and missingness, then input order.

  • IQR: any feature value outside its fences.
  • z-score: any feature with |z| above the threshold.
  • Isolation Forest: contamination 0.05.
  • PCA + DBSCAN: noise points after projecting to 2 components (eps 0.3, min_samples 5; needs at least 5 rows).
  • Mahalanobis: distance beyond the chi-square 97.5% quantile.

is_outlier is True when a strict majority of the methods that could vote flag the row, with at least two methods voting. It is never null: a row with too little evidence is False.

max_multivariate_features = 15iqr_multiplier = 1.5outlier_zscore_threshold = 3.0random_state = 42

Columns added per row: eda_outlier_iqr, eda_outlier_zscore, eda_outlier_iforest, eda_outlier_pca_dbscan, eda_outlier_mahalanobis, eda_outlier_votes, eda_outlier_methods_available, is_outlier, mahalanobis_distance, mahalanobis_pvalue.

↓row-level diagnostics

5 · Write the outputs

once per run
12

Charts

only if include_plots = True

Features are plotted in one shared order: proposal rank first, then the remaining columns by quality and missingness. Each chart shows at most max_features_per_plot features; categorical charts keep the top categories and target charts the top target levels.

include_plots = Truemax_features_per_plot = 30max_categories = 20max_target_levels_for_plots = 20
13

Tables and annotated data

  • eda_summary.json and CSV tables under tables/ (overview, data_quality, numeric, categorical, correlation, target, feature_selection, multivariate, geospatial).
  • eda_annotated_data.parquet: every input row with the outlier columns of step 11, geometry preserved.
14

HTML report

only if include_html_report = True

report.html combines the tables and charts. The run also returns proposed_features, the features with action use.

include_html_report = True

Things to know before choosing values

  • The outlier vote judges only the 15 best-ranked numeric features. Without a target there is no proposal, so the ranking falls back to data quality and missingness. Raise max_multivariate_features to judge more columns.
  • PCA (step 10) still uses the first numeric columns in table order and can include a numeric target or ID; treat it as an overview only.
  • Every test here sees all rows, including those the ML pipeline later holds out. That is why the proposal is a starting shortlist and why the EDA diagnostic columns are excluded from features.
  • With target_task="auto", numeric crop codes are analysed as a regression target. Set classification explicitly.
  • Only is_outlier is meant to travel to the ML pipeline (as metadata for excluding rows from training or raising inspection priority), never as a model feature.
