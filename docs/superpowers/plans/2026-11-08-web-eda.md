# Web EDA implementation plan

**Goal:** Launch the existing EDA pipeline from a completed, owned parcel analysis,
with all analytical configuration and explicit input-column selection in a dialog.

**Architecture:** Reuse FastAPI, React, PostgreSQL and the heavy worker lane. Store
each EDA submission separately in `eda_runs`, linked to its user and parcel run.
Read only the verified statistics artifact; allocate a fresh output directory for
every EDA. EDA never resets or modifies its source run. Downloads remain owner scoped.

**Scope:** The user's request defines the interaction. The implementation uses
a native modal dialog rather than a browser popup, preserving session and focus.
All `EDAConfig` scientific/reporting options are editable. Paths, artifact filenames,
schema version and reset behavior are visible as managed settings. Selected target
and ID must be included in selected input columns. Geometry can be included for
geospatial diagnostics. New analyses preserve earlier EDA outputs.

- [x] Configuration/selection tests; dataclass-derived schema and strict validation.
- [x] Additive `eda_runs` table, completed-owner guards, column metadata, immutable
  idempotent submission, history/status and contained attachment downloads.
- [x] Worker EDA task, source checksum check, selected-column read, isolated output,
  saved config/logs, registered files and ZIP; failure/interruption state.
- [x] Completed-run EDA buttons, accessible configuration/columns dialog, status
  history and result downloads; reuse grouped ConfigForm.
- [x] Validate configuration coverage, isolation, gating, queue behavior and real
  synthetic EDA execution. Type-check/build where available. Document deployment.

## Review focus

- Reject foreign or unfinished parent runs on the server, regardless of UI state.
- Reject arbitrary input/output paths and unrecognized config fields.
- Parent artifacts and old EDA outputs must survive failures and reruns unchanged.
- Only selected input columns reach EDA; target/ID cannot be silently missing.
- HTML downloads are attachments; report/plot relative paths survive ZIP extraction.
- Repeated submissions with the same request ID must not enqueue duplicate work.

## Report viewing and failed-run investigation follow-up

Implemented an automatic Report tab for pending-to-complete transitions while
the EDA window is open, and a direct Open report history link. The authenticated
report endpoint embeds registered PNGs and applies an opaque-origin sandbox CSP;
the proxy preserves this policy. Original HTML/ZIP downloads remain available.
New failures retain a traceback and expose an owner-only redacted log download.

Reproduced a singular KDE covariance error in scatter-matrix generation using
the actual failed-run input. Constant/missing features now remain in statistical
tables but are omitted from that plot; finite complete rows and histogram
diagonals avoid degenerate density estimates. All ten previously failed EDA
configurations completed with the fixed Docker image in fresh temporary folders,
including three whose original inputs remain on the previous named volume.
Existing result folders and database history were preserved.

Verification: 62 backend/EDA tests, 7 frontend tests, production UI build, Docker
API/UI builds, Ruff and whitespace checks passed. The user approved restarting
the updated application. Browser automation host was unavailable; visual browser
inspection was not performed.
