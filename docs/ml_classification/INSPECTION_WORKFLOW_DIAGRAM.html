Inspection priority workflow

How the predict step turns each parcel's prediction and its supporting evidence into one of seven inspection priorities, a check type and the reasons behind them. Read from the code in src/ml_classification/step_05_predict/libraries/inspection_priority/. Defaults are those of ClassificationPipelineConfig.

flag = default input that controls the step only if … step is conditional

1 · Evidence collected before this step

one value per parcel, from three pipelines
a

From ML classification

  • Predicted class from the vote of the selected models.
  • Rank confidence: HIGH, MEDIUM or LOW, from how consistently the models rank the predicted class.
  • Class reliability: HIGH, MEDIUM or LOW, the out-of-fold precision of the predicted class, frozen in the evaluate step.
  • Declared class: the target column, when the parcel has one.
rank_confidence_enabled = Trueclass_reliability_enabled = True
b

From parcel statistics and EDA

  • Data reliability: data_reliability_score, the share of pixel values that were really observed and not filled (0 to 1).
  • Geometry complexity: geom_shape_complexity_score, higher for small, irregular or elongated parcels.
  • Outlier flag: is_outlier from EDA, optional metadata joined by parcel ID.
inspection_data_reliability_column = "data_reliability_score"inspection_geometry_complexity_column = "geom_shape_complexity_score"
1

Check that scoring can run

only if inspection_scoring_enabled = True

The confidence level, data-reliability and geometry-complexity columns must exist. If one is missing the whole step is skipped with a warning and predictions are saved without inspection columns.

inspection_scoring_enabled = True
↓six inputs per parcel

2 · Turn the evidence into comparable signals

per parcel
2

Compare the declaration with the prediction

Codes are normalised first, so 1.0 and "1" are the same class. Result in label_prediction_status: SAME, DIFFERENT, NO_DECLARATION (no declared class) or UNAVAILABLE (no prediction).

3

Express each uncertainty as a risk from 0 to 1

  • confidence_risk: HIGH = 0, MEDIUM = 0.5, LOW = 1.
  • data_risk = 1 − data reliability. Scores outside 0 to 1 are treated as missing.
  • geometry_risk = the percentile rank of the parcel's complexity among all predicted parcels. It is relative: 0.5 is the median parcel of this run.

Geometry level (geometry_complexity_level, LOW, MEDIUM or HIGH). In percentile mode a parcel is MEDIUM only when its rank is at least 0.50 and its complexity score at least 0.60, HIGH when its rank is at least 0.75 and its score at least 0.90. A run of simple parcels therefore stays LOW. absolute mode uses the scores alone. For scale: compact parcels score about 0.1–0.3, 2:1 strips 0.35–0.5, 3:1 strips 0.5–0.7, 5:1 strips 0.75–0.95.

inspection_geometry_threshold_mode = "absolute"inspection_medium_geometry_risk_threshold = 0.50inspection_high_geometry_risk_threshold = 0.75inspection_medium_geometry_complexity_threshold = 0.60inspection_high_geometry_complexity_threshold = 0.90
4

Set the data-reliability boundaries for this run

  • percentile: low = the smaller of 0.60 and the 5th percentile of the scores; medium = the smaller of 0.80 and the 25th percentile. This only relaxes the limits, so a season with ordinary cloud gaps does not make most parcels weak evidence.
  • absolute (default): 0.60 and 0.80 exactly as configured.

The applied values are saved on every row and in predict_summary.json; rules, reasons and reports all read the saved values.

inspection_data_reliability_threshold_mode = "absolute"inspection_low_data_reliability_threshold = 0.60inspection_medium_data_reliability_threshold = 0.80inspection_low_data_reliability_percentile = 0.05inspection_medium_data_reliability_percentile = 0.25
5

Compute the diagnostic score

inspection_score = 100 × (0.60 × confidence risk + 0.25 × data risk + 0.15 × geometry risk), with a score-only band in inspection_need_base (HIGH from 50, MEDIUM from 25). It never decides the priority band, but it orders the parcels inside a band in the queue (step 11), so the weights set the visiting order.

inspection_model_weight = 0.60inspection_data_weight = 0.25inspection_geometry_weight = 0.15inspection_medium_score_threshold = 25.0inspection_high_score_threshold = 50.0

3 · Decide the priority

rules, first match wins
6

Handle parcels the table cannot judge

  • Unknown (REQUIRED_EVIDENCE_UNAVAILABLE): no prediction, invalid rank confidence, or missing data reliability or geometry.
  • Medium (NO_DECLARATION): valid evidence but no declared class to compare with.
  • Medium (CLASS_RELIABILITY_UNAVAILABLE): class reliability is enabled but the predicted class had too few out-of-fold predictions to be judged.
7

Apply the 20-rule decision table

Conditions in a row are combined with AND; the first matching row wins. Data reliability high means strictly above the applied medium boundary of step 4. Geometry good means geometry_complexity_level LOW (step 3). With class reliability disabled, its column is treated as High.

8

Raise outliers by one band

only if inspection_include_outlier = True and the is_outlier column exists

A parcel with is_outlier = True moves up one band: Very Low to Low, Low to Low–Medium, and so on up to High to Very High. Very High and Unknown do not change. Only real True values count (or 1); text and missing values do not. The rule ID is kept, and inspection_outlier_adjusted records the change.

inspection_include_outlier = False
9

Decide what kind of check is needed

  • NONE: Very Low and Low. Also Low–Medium and Medium when the declaration matches the prediction, unless matching declarations are to be checked.
  • DECLARATION_CONFLICT: declaration differs and the priority is Medium–High, High or Very High.
  • INSUFFICIENT_EO_EVIDENCE: everything else, including parcels that an outlier raised from NONE to Low–Medium or above.
inspection_check_matching_declarations = False
↓priority and check type

4 · Explain and queue

outputs in 05_predict/
10

Write the reasons

inspection_reasons lists the codes that apply, separated by |: declaration conflict or difference, insufficient evidence, low or medium model confidence, low or medium data reliability, medium or high geometry complexity (the geometry level of step 3), class reliability, no declaration, and the outlier increase.

11

Save, report and queue

All columns go into final_predictions.joblib and the preview CSV; counts per priority, check type and status go into predict_summary.json. The report queue is ordered by final priority; inside each band the parcel with the higher inspection_score comes first, parcels without a score come last and remaining ties keep input order. recalculate_prediction_quality() re-applies steps 2 to 10 with new settings without refitting; the table is applied first each time, so outlier increases never accumulate.

Things to know before choosing values

  • The weights decide the order of parcels inside a priority band; the two score thresholds only band the score into inspection_need_base. To change who gets inspected, change the geometry or data-reliability thresholds, the outlier option or the matching-declarations option.
  • Geometry needs both a high rank and a high complexity score in percentile mode. Set both complexity thresholds to 0 to return to the rank-only policy, where about half of every run is "not good".
  • In percentile mode up to about a quarter of the parcels fall at or below the medium data boundary and are therefore Medium, whatever their confidence.
  • With fewer than 3 voting models the confidence comes from the predicted-class probability, so parcels still get a priority. Rank agreement remains the stronger evidence.
  • By default a matching declaration with inconclusive evidence is not queued. Set inspection_check_matching_declarations=True to review those parcels as well.
  • An outlier increase is extra review priority, not stronger proof of a wrong declaration. The library default is off.
